# Screen Inventory — ZPS-OMS

Every application route, the permission(s) that gate it, and the roles that can reach it with the seeded configuration. The server re-checks permissions in the domain layer regardless of the page gate. Evidence: `docs/evidence/route-audit.md` (generated by `npm run audit:routes`).

## Public (no sign-in)
| Route | Screen | Notes |
|---|---|---|
| `/` | Landing | Scope, exclusions, status; no statistics |
| `/about` | About ZPS-OMS | Principles, governance, status |
| `/features` | Features | — |
| `/modules` | Modules | MVP/later distinction |
| `/contact` | Contact | **No contact details** until supplied by the Service |
| `/login` | Secure sign-in | Synthetic role simulator, clearly labelled; no registration |

## Shared shell (all authenticated)
Institutional band, crest lock-up, permission-filtered navigation, breadcrumb (org context), synthetic-data banner with active role & scope, help, notifications badge, profile, sign-out. Mobile drawer (Escape/backdrop closes).

| Route | Screen | Gate | Roles (seeded) |
|---|---|---|---|
| `/app` | Role dashboard (13 variants) | any active assignment | All |
| `/app/approvals` | Approvals & queues | request.view or request.assign | DIG, HQC, commanders, staff ops, formation admin, auditor, ops staff |
| `/app/requests` | Request register | request.view | as above |
| `/app/requests/new` | New request | request.create | HQC, staff ops, formation admin, ops staff |
| `/app/requests/[id]` | Request detail, actions, history, route | view rule (scope or pending-with-me) | per record |
| `/app/fleet` | Fleet register | fleet.view | HQC, commanders, staff ops, formation roles, fleet officer, auditor |
| `/app/fleet/new` | Add vehicle | fleet.manage | Fleet officer |
| `/app/fleet/[id]` | Vehicle detail, service history | fleet.view in scope | per record |
| `/app/fleet/maintenance` | Maintenance workbench | maintenance.view | as fleet register |
| `/app/fleet/maintenance/new` | New maintenance request | maintenance.create | staff ops, formation admin, fleet officer |
| `/app/fleet/maintenance/[id]` | Maintenance detail & actions | maintenance.view in scope | per record |
| `/app/assets` | Asset register | asset.view | HQC, commanders, staff ops, formation roles, custodian, auditor |
| `/app/assets/new` | Register asset | asset.register | Asset custodian |

Screens from the master prompt not built as separate pages: "Division information" and "Formation information" are on the command dashboards and `/app/org/[id]`; "Asset custody" and "Asset inspection" are actions on `/app/assets/[id]`; "Application settings" is read-only on `/app/platform`; "Administrative workflow configuration" is read-only (`/app/workflows`, DEC-008).
