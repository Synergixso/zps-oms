## 8. New-direction gap analysis (Parts 4–13)

| Requirement | Baseline | What is needed |
|---|---|---|
| IG as the supreme authority; DIG Operations reports to the IG; DIG Administration and DIG Special Duties subordinate and outside the Operations chain | Only implicit: roles 02 and 03 exist, but nothing models who commands or reports to whom | Command positions for IG and all four DIG offices; IG with no superior; relationships that make it impossible to address a directive upward |
| Rank, position, appointment and application role as separate attributes | Rank on personnel records; roles on accounts; **no positions or appointments** | `command_positions`, appointments of users to positions with history, position types with indicative rank; role mapping recorded but not automatic |
| Configurable reporting relationships with types, dates, authorising reference, history; loop prevention | None | `reporting_relationships` with primary command, primary reporting, parallel reporting and administrative coordination; cycle check on every insert |
| Top-down directives with authority validation, acknowledgement, forwarding to the next level, progress, completion, consolidated status, closure | None (approval chains exist, but approvals are not instructions) | Directive register with categories (command directive, administrative instruction, operations administrative task, personnel-related assignment), downward-only rule, events, notifications |
| Bottom-up status reports with review, return, resubmission, forwarding, closure | None | Report register with recipients, reviews and forwarding |
| Parallel reporting: one report, many recipients, separate acknowledgements | None | Report recipients table; one reference; per-recipient state |
| Mobile Unit chain Constable → … → Area Commander and the Area Commander's two channels | Mobile Unit, company, platoon and sections exist in the organisation tree; no command chain | Synthetic positions and relationships for the chain; channel A (District Operations Officer, OC District) and channel B (Staff I/II → Commander → Commissioner → DIG → IG) |
| Acting appointments and delegations with expiry | Approval delegations only | Acting appointments with delegated actions, authoriser, dates; expiry restores ordinary authority |
| Conflicting tasking from parallel channels | None | Conflict records referred to the nearest common superior; decision recorded; no automatic precedence |
| Pages and dashboards for the command roles (Part 8) | None | Command overview, directives received and issued, reports to review and submitted, acting status, conflicts, structure, integrated into each role's navigation and dashboard |
| Automations (Part 12) | None | Acknowledgement and report reminders, overdue escalation, acting expiry |
| Users who hold an appointment but none of the 31 roles (Inspector, Sergeant, Constable, Area Commander) | Such users cannot use the application at all | **Owner decision needed**: no new RBAC role may be invented. Proposed: appointment-only access limited to the user's own directives and reports, behind a platform setting, recorded as requiring validation |
| Mapping of positions to existing roles (Section Head ↔ Section/Platoon Commander; Formation Commanding Officer ↔ Divisional Commander; Area Commander ↔ Company Commander?) | Not defined | Record proposed mappings as configuration and flag them for institutional validation; never conflate automatically |
