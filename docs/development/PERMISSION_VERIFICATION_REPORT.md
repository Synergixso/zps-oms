## How permissions are enforced

- Every domain function is `async (db, actor, …)` and checks permission **and** organisational scope on the server (`policy.requirePermission`, `policy.can`, `scopeFor`); pages and navigation only mirror those checks. Hiding a link is never the control.
- Coverage: **U** assigned unit · **S** assigned unit and all subordinate units (via `org_unit_closure`) · **N** national, only for assignments held at Service HQ. Deny by default: a permission a role does not list is refused.
- Approval authority is not a permission: it needs an active delegation at the record's unit or an ancestor and a BUSINESS-category role there (`policy.approvalUnitFor`). Self-approval and deciding two levels of one chain are refused.
- Out-of-scope records return a neutral 404 (`loadOr404`); refusals are audited as SECURITY events.
