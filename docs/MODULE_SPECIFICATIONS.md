# Module Specifications — ZPS-OMS

Each module lists purpose, implementation location, functions, and acceptance criteria with their verification. Requirement IDs refer to REQUIREMENTS_TRACEABILITY.md.

## M01 Organisation and Formation Registry — `src/server/domain/org.ts`
- **Purpose:** single configurable, effective-dated directory of in-scope organisations.
- **Functions:** list (as-at date, include inactive), detail, relationship history, propose change, decide change, apply due changes.
- **Acceptance:** only `org.propose` holders propose; a different delegated approver decides; effective-dated changes do not rewrite history or grant access. *Verified:* TS-15 (2 tests).

## M02 Identity, Roles and Access — `iam.ts`, `policy.ts`, `sessions.ts`
- **Functions:** provision, assign/revoke role+scope, grant/revoke delegation, suspend/reactivate/deactivate, access reviews, session lifecycle.
- **Acceptance:** no URL/payload/record-ID manipulation broadens access; every protected action validates user, role, scope, record state server-side. *Verified:* TS-02, TS-04..TS-10, route audit (20 users × 39 routes).

## M03 Administrative Requests — `requests.ts`
- **Functions:** create, edit (draft/returned), submit, assign, approve (multi-level), return, reject, cancel, start, complete, close, reopen, history, inbox, queues, overdue.
- **Acceptance:** FR-WF-001..007. *Verified:* TS-03, TS-11, TS-12, WF tests.

## M04 Fleet Register and Maintenance — `fleet.ts`
- **Functions:** vehicle register (search/filter), create, admin update, maintenance lifecycle, service history, due-date monitor.
- **Excluded fields:** GPS, location, route, mission, crew, deployment.
- *Verified:* WF fleet lifecycle, TS-05/06.

## M05 General Non-sensitive Assets — `assets.ts`
- **Functions:** register (allowlist + term screening), issue/return, transfer/receive, inspect, repair, dispose, event history.
- *Verified:* WF asset lifecycle; prohibited-class test; TS-04.

## M06 Dashboards and Reporting — `reports.ts`, `src/app/app/page.tsx`
- **Functions:** 13 role dashboards; `computeSummary` & `breakdownByOrg` aggregates; 4 report definitions; CSV export.
- **Acceptance:** aggregate-first; field allowlist; exports logged; no personnel/readiness metrics. *Verified:* TS-01, TS-14.

## M07 Availability/Scheduling — not implemented (later, separate approval).
## M08 Correspondence metadata — not implemented (later, separate approval).

## M09 Notifications — `core.notify`, `/app/notifications`
In-app only; generated by workflow events; mark-all-read scoped to the caller.

## M10 Audit and Security — `audit.ts`, `auditq.ts`
Hash-chained append-only events (DB triggers), explorer, security events view, evidence export, denied-access logging (domain + page level). *Verified:* TS-13.

## M11 Platform Operations — `/app/platform`
App/DB health (`PRAGMA quick_check`), schema version, audit chain status, read-only settings, row counts. No business data.
