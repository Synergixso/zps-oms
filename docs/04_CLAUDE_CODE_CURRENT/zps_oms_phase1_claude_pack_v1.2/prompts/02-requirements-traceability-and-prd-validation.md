# Prompt 02 — Requirements Traceability and PRD Validation

Review all candidate ZPS-OMS requirements against the approved scope and the Phase 1 evidence register.

For every requirement, populate: ID, concise statement, source/evidence, stakeholder owner, actor, process, priority, acceptance criteria, data fields, classification, lawful purpose (pending Legal review), organisation scope, permissions, dependencies, existing system overlap, exclusion check, test ID, status and approval reference.

Disposition each item as Accept, Revise, Defer or Reject. No requirement is “approved” unless an authorised owner and evidence are recorded. Distinguish public-source fact, user-defined project boundary, hypothesis and proposal.

Create a requirements traceability matrix from business objective to process, requirement, design component, test case and approval gate. Check that no requirement introduces a district/station/post tenant, training-system capability, tactical command, dispatch, patrol route, tracking, intelligence, surveillance, case/evidence or weapons/armoury feature.

No new funding, paid tool, external API, hosting or procurement is allowed at this stage. No application implementation. Outputs are documentation updates and open decisions only.
