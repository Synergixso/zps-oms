# Prompt 03 — Local Synthetic Prototype Plan (Planning Only)

Prepare a technical plan for a small local prototype using synthetic data only. Do not write application code yet.

Prototype candidates, subject to user direction and toolchain approval:
1. Configurable organisation directory with synthetic Provincial Division and formation entities (no hard-coded reporting assumptions).
2. Mock identity and organisation-scoped server-side authorisation, using fictitious users only.
3. One generic non-sensitive administrative request workflow with a fictitious delegated approval matrix clearly labelled as demonstration-only.

Do not prototype fleet details, live duty scheduling or equipment inventories until process ownership, existing systems and safe field boundaries have been validated. Public Technical Services mandate includes relevant ICT and vehicle/mechanical-maintenance responsibilities, so duplication must be checked.

Propose a simple maintainable local architecture; justify every dependency. Do not select hosting, cloud, identity provider or external integration. Do not enable public registration, external notifications, real e-mail/SMS, telemetry or data export to third parties.

Zero funding: use only tools already available and permitted. No upgrade, credit purchase, subscription, paid APIs, hosting or hardware. If a cost is required, stop and present an open decision.

Deliver: local architecture sketch, synthetic data dictionary, organisation/role permission matrix, threat model, test plan, repository changes proposed, dependency/licence review and rollback plan. Mark all design choices provisional until reviewed.
