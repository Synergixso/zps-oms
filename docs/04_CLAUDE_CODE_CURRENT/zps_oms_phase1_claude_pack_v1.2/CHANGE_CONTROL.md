# Change Control

Any proposed change to the product boundary, organisation hierarchy, data scope, business workflow, authentication, hosting, integrations, retention or financial approach must be recorded before implementation.

Each change request should contain: request ID, requestor role, date, reason/evidence, affected requirement IDs, scope impact, data/privacy/security impact, existing-system impact, toolchain/cost impact, alternatives, decision authority, outcome, conditions and decision evidence.

No change that adds excluded tactical/operational capabilities, expands to districts/stations/posts, or requires funding may be silently accepted. A paid requirement pauses current-stage work and requires separate future approval.
